شرح مشروع HabibaVelora

فكرة المشروع: متجر إلكتروني لعرض الإكسسوارات، إدارة المنتجات من لوحة تحكم، استقبال الطلبات، متابعة حالة الطلب، طلبات المرتجع، وربط تنبيهات الطلبات بتليجرام.

التقنيات المستخدمة: Next.js، JavaScript، CSS، و Vercel Blob لتخزين المنتجات والصور والطلبات.

هيكل المشروع العام

  • pages: صفحات Next.js ومسارات API.
  • public: ملفات JavaScript التي تعمل داخل المتصفح، الصور، وملفات السيو.
  • lib: ملفات مساعدة مشتركة مثل محتوى الصفحات وتخزين المنتجات.
  • components: مكوّن مشترك يعرض الصفحات القديمة داخل Next.js.
  • styles.css: تنسيق الموقع بالكامل للموبايل واللاب والوضع الداكن.

الصفحات الأساسية

pages/index.js

صفحة المتجر الرئيسية. تقرأ المنتجات من التخزين عند كل تحميل، ثم تمررها للواجهة حتى تظهر المنتجات بسرعة بدون انتظار طويل من المتصفح.

pages/admin.js

صفحة لوحة التحكم. تستخدم نفس نظام تحميل المنتجات حتى تعرض المخزون الحالي، وتسمح بإضافة وتعديل المنتجات والطلبات.

pages/cart.js

صفحة السلة وتأكيد الطلب. العميل يراجع المنتجات، يكتب بياناته، يختار المحافظة والمركز وطريقة الدفع، ثم يتم حفظ الطلب.

pages/product.js

صفحة المنتج المستقلة. تعرض صور المنتج، الألوان، اختيارات السعر، الكمية، التقييمات، والمنتجات المشابهة.

pages/after-sales.js

صفحة المرتجعات. العميل يكتب رقم الطلب وبيانات المرتجع، ويتم حفظ الطلب ومتابعته من لوحة التحكم.

pages/order-tracking.js

صفحة متابعة الطلب. العميل يدخل رقم الطلب أو الفاتورة أو الهاتف، فتظهر له حالة الطلب الحالية مثل قيد التجهيز أو تم الشحن أو تم التسليم.

pages/follow.js

صفحة مستقلة لروابط المتابعة مثل واتساب وإنستجرام، ومربوطة من الشريط العلوي.

ملفات API

pages/api/products.js

مسؤول عن قراءة وحفظ المنتجات. القراءة متاحة للموقع، أما الحفظ فيحتاج كلمة مرور الإدارة حتى لا يغير أي شخص بيانات المنتجات.

pages/api/images.js

يستقبل صور المنتجات بعد ضغطها من المتصفح، ويتأكد من صلاحية الصورة، ثم يحفظها في Vercel Blob ويرجع رابط آمن لعرضها.

pages/api/product-image.js

يعرض صورة محفوظة في التخزين الخاص عن طريق رابط داخلي، بدل كشف رابط التخزين المباشر.

pages/api/orders.js

يحفظ الطلبات ويقرأها ويحدّث حالتها. كما يدعم حذف الطلبات من لوحة التحكم عند الحاجة.

pages/api/reviews.js

يحفظ تقييمات العملاء للمنتجات. التقييمات لا تظهر تلقائيًا إلا بعد أن يضيفها العميل.

pages/api/telegram.js

يرسل تفاصيل الطلب الجديد إلى بوت تليجرام عند نجاح عملية الشراء، بشرط وجود إعدادات البوت في متغيرات البيئة.

ملفات الواجهة داخل public

public/main.js

الملف الرئيسي للمتجر ولوحة التحكم. يحتوي على إدارة المنتجات والسلة والمفضلة والطلبات، ويقوم بتحديث الواجهة عند إضافة منتج أو تعديل حالة الطلب.

  • تحميل المنتجات من التخزين.
  • إضافة المنتج للسلة مع اللون والمقاس واختيار السعر.
  • ضغط صور المنتج تلقائيًا قبل الرفع.
  • حفظ المنتجات والطلبات في قاعدة التخزين.
  • إدارة لوحة التحكم وتحديث حالة الطلب.
  • تبديل صور الواجهة كل 3 ثواني.

public/product-page.js

مسؤول عن صفحة المنتج فقط. يقرأ المنتج المطلوب من الرابط، يعرض صوره واختياراته، ويدعم إضافة التقييمات واختيار أسعار مختلفة لنفس المنتج.

public/after-sales.js

يدير نموذج المرتجع، يملأ المحافظات والمراكز، يحفظ طلب المرتجع، ويعرض معاينة للبيانات قبل الإرسال.

public/order-tracking.js

يبحث عن الطلب من خلال API ويعرض حالته للعميل بطريقة بسيطة وواضحة.

public/script.js

يحتوي على بيانات المحافظات والمراكز، وتكلفة الشحن الافتراضية، ويجهز القوائم المنسدلة في السلة والمرتجع.

public/tracking.js

ملف جاهز لإضافة أكواد التحليلات أو البكسل عند الحاجة، بدون التأثير على باقي ملفات الموقع.

ملفات lib و components

lib/page-content.js

يحتوي على HTML الأساسي للصفحات التي يتم عرضها داخل Next.js. الهدف منه فصل محتوى الصفحة عن ملفات التشغيل والمنطق.

lib/products-store.js

ملف صغير يقرأ ويكتب ملف المنتجات products.json في Vercel Blob. هذا يمنع ضياع المنتجات عند تغيير شكل الموقع أو رفع نسخة جديدة.

components/LegacyPage.js

مكوّن مشترك يضيف عنوان الصفحة والوصف والسكريبتات المطلوبة، ويمرر المنتجات الأولية للمتصفح.

التنسيق والتصميم

styles.css

يحتوي على نظام الألوان، تصميم الكروت، الهيدر، السلة، لوحة التحكم، صفحات المنتج والمرتجع، ودعم الموبايل والوضع الداكن.

تم الاعتماد على متغيرات CSS لتسهيل تغيير الألوان من مكان واحد، مع Media Queries لضبط الواجهة على أحجام الشاشات المختلفة.

تخزين المنتجات والصور

المنتجات لا تُحفظ داخل ملفات الواجهة، بل تُحفظ في Vercel Blob. لذلك عند تعديل شكل الصفحة أو رفع نسخة جديدة، تظل المنتجات المضافة من لوحة التحكم موجودة.

صور المنتجات يتم ضغطها في المتصفح إلى WebP قبل الرفع، ثم تُرسل إلى API الصور وتحفظ في التخزين.

مسار الطلب

  1. العميل يختار المنتج واللون والمقاس واختيار السعر.
  2. المنتج يضاف للسلة مع كل تفاصيله.
  3. العميل يكتب بيانات الشحن والدفع.
  4. يتم حفظ الطلب في التخزين.
  5. تصل رسالة تليجرام للإدارة بتفاصيل الطلب.
  6. الإدارة تغيّر حالة الطلب من لوحة التحكم.
  7. العميل يتابع الحالة من صفحة متابعة الطلب.

نقاط مهمة للمناقشة

  • فصل المنتجات عن ملفات الكود يمنع ضياع البيانات بعد أي تعديل.
  • ضغط الصور يحافظ على سرعة الموقع حتى مع عدد كبير من المنتجات.
  • لوحة التحكم محمية بكلمة مرور.
  • الطلبات والتقييمات والمنتجات لها API مستقل.
  • الموقع يدعم الموبايل واللاب والوضع الداكن.
